# 测试搜索和分类功能

## 问题描述
搜索和分类功能的界面正常，但点击后商品列表没有变化。

## 排查步骤

### 1. 检查数据库中的商品数据
```sql
-- 查看所有商品及其分类
SELECT id, product_name, category, status FROM product;

-- 查看有哪些分类
SELECT DISTINCT category FROM product;

-- 测试分类查询
SELECT * FROM product WHERE category = '蔬菜' AND status = '1';

-- 测试关键词搜索
SELECT * FROM product WHERE product_name LIKE '%测试%' AND status = '1';
```

### 2. 检查后端日志
启动后端服务后，在控制台查看：
- Controller 层是否收到了正确的参数（keyword, category）
- Service 层是否正确传递了参数
- 查询结果的数量

### 3. 检查前端请求
在微信开发者工具的控制台查看：
- 发送的请求参数是否正确
- API 返回的数据是否正确

### 4. 可能的问题

#### 问题1：数据库中商品的 category 字段值与前端不匹配
**解决方案**：
- 前端使用：'蔬菜', '水果', '粮油', '肉禽蛋'
- 检查数据库中的实际值是否一致

#### 问题2：商品的 status 字段不是 '1'
**解决方案**：
- 检查商品状态，确保有上架的商品（status = '1'）

#### 问题3：MyBatis XML 配置问题
**解决方案**：
- 检查 ProductMapper.xml 是否正确配置
- 确保参数名称匹配

## 测试用例

### 测试1：分类筛选
1. 点击"蔬菜"分类
2. 预期：只显示分类为"蔬菜"的商品
3. 检查后端日志：category 参数应该是 "蔬菜"

### 测试2：关键词搜索
1. 输入关键词"西红柿"
2. 点击搜索按钮
3. 预期：显示包含"西红柿"的商品
4. 检查后端日志：keyword 参数应该是 "西红柿"

### 测试3：组合查询
1. 选择"蔬菜"分类
2. 输入关键词"西红柿"
3. 点击搜索
4. 预期：显示分类为"蔬菜"且包含"西红柿"的商品

## 调试建议

1. **先测试后端接口**：
   使用 Postman 或 curl 直接测试后端接口：
   ```bash
   curl -X POST http://localhost:8080/api/product/list \
     -H "Content-Type: application/json" \
     -d '{
       "page": 1,
       "pageSize": 10,
       "category": "蔬菜"
     }'
   ```

2. **检查前端发送的请求**：
   在微信开发者工具控制台查看 Network 请求

3. **查看后端日志**：
   启动后端服务，查看控制台输出的日志
