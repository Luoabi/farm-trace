# 驾驶舱（Dashboard）设计方案

## 一、驾驶舱应该包含的内容

### 1. 核心统计数据卡片 📊

#### 超级管理员视图
- **总批次数**：所有农户的批次总数
- **总商品数**：所有农户的商品总数
- **总订单数**：系统中所有订单数量
- **总用户数**：系统中所有用户数量
- **总销售额**：所有订单的总金额
- **待处理订单**：待发货订单数量
- **上链记录数**：已上链的记录总数
- **活跃农户数**：本月有活动的农户数量

#### 农户视图
- **我的批次数**：当前农户的批次总数
- **我的商品数**：当前农户的商品总数
- **我的订单数**：当前农户的订单数量
- **我的销售额**：当前农户的销售总额
- **种植中批次**：状态为种植中的批次数
- **已收获批次**：状态为已收获的批次数
- **待发货订单**：需要发货的订单数
- **本月生长记录**：本月添加的生长记录数

#### 顾客视图
- **我的订单数**：顾客的订单总数
- **待支付订单**：待支付的订单数
- **待收货订单**：已发货待收货的订单数
- **已完成订单**：已完成的订单数

### 2. 数据趋势图表 📈

#### 生产趋势图（折线图）
- **X轴**：时间（月份/季度）
- **Y轴**：批次数量
- **数据来源**：
  - 超级管理员：所有批次按月统计
  - 农户：自己的批次按月统计
- **SQL查询**：
```sql
SELECT 
  DATE_FORMAT(create_time, '%Y-%m') as month,
  COUNT(*) as count
FROM batch
WHERE status != -1
  AND (farmer_id = ? OR ? = 'SUPER_ADMIN')  -- 根据角色过滤
GROUP BY DATE_FORMAT(create_time, '%Y-%m')
ORDER BY month DESC
LIMIT 12
```

#### 商品分布图（饼图）
- **数据**：各类商品的数量占比
- **分类**：水果、蔬菜、粮食等
- **数据来源**：
  - 超级管理员：所有商品按分类统计
  - 农户：自己的商品按分类统计
- **SQL查询**：
```sql
SELECT 
  category,
  COUNT(*) as count
FROM product
WHERE status = 1
  AND (farmer_id = ? OR ? = 'SUPER_ADMIN')
GROUP BY category
```

#### 订单状态分布图（环形图）
- **数据**：各状态订单的数量
- **状态**：待支付、待发货、已发货、已完成
- **SQL查询**：
```sql
SELECT 
  order_status,
  COUNT(*) as count
FROM `order`
WHERE (farmer_id = ? OR customer_id = ? OR ? = 'SUPER_ADMIN')
GROUP BY order_status
```

#### 销售趋势图（柱状图）
- **X轴**：时间（月份）
- **Y轴**：销售额
- **SQL查询**：
```sql
SELECT 
  DATE_FORMAT(create_time, '%Y-%m') as month,
  SUM(total_price) as total_sales
FROM `order`
WHERE order_status IN (3, 4)  -- 已发货、已完成
  AND (farmer_id = ? OR customer_id = ? OR ? = 'SUPER_ADMIN')
GROUP BY DATE_FORMAT(create_time, '%Y-%m')
ORDER BY month DESC
LIMIT 12
```

### 3. 最近活动时间线 ⏰

#### 显示内容
- 最近10条系统活动记录
- 包括：批次创建、商品上架、订单创建、生长记录添加等

#### 数据来源
需要创建一个活动日志表：
```sql
CREATE TABLE activity_log (
  id VARCHAR(36) PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL,
  user_name VARCHAR(50) NOT NULL,
  action_type VARCHAR(20) NOT NULL,  -- CREATE, UPDATE, DELETE
  module VARCHAR(20) NOT NULL,       -- BATCH, PRODUCT, ORDER, GROWTH_RECORD
  description TEXT,
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id),
  INDEX idx_create_time (create_time)
);
```

#### SQL查询
```sql
SELECT 
  user_name,
  action_type,
  module,
  description,
  create_time
FROM activity_log
WHERE (user_id = ? OR ? = 'SUPER_ADMIN')
ORDER BY create_time DESC
LIMIT 10
```

### 4. 待处理任务列表 ✅

#### 超级管理员任务
- 待审核的批次申请
- 待处理的用户反馈
- 系统异常告警
- 数据异常提醒

#### 农户任务
- 待发货订单（order_status = 2）
- 库存不足商品（需要补货）
- 即将收获的批次（harvest_time 临近）
- 需要更新的生长记录（超过7天未更新）

#### SQL查询示例
```sql
-- 待发货订单
SELECT 
  order_number,
  product_name,
  customer_name,
  create_time
FROM `order`
WHERE farmer_id = ?
  AND order_status = 2
ORDER BY create_time ASC
LIMIT 10;

-- 即将收获的批次
SELECT 
  batch_number,
  product_name,
  harvest_time
FROM batch
WHERE farmer_id = ?
  AND status = 1
  AND harvest_time BETWEEN NOW() AND DATE_ADD(NOW(), INTERVAL 7 DAY)
ORDER BY harvest_time ASC;
```

### 6. 数据对比分析 📊

#### 同比/环比数据
- 本月 vs 上月
- 本季度 vs 上季度
- 本年 vs 去年

#### 显示内容
- 批次增长率
- 订单增长率
- 销售额增长率
- 用户增长率

#### SQL查询示例
```sql
-- 本月数据
SELECT COUNT(*) as current_month_count
FROM batch
WHERE farmer_id = ?
  AND DATE_FORMAT(create_time, '%Y-%m') = DATE_FORMAT(NOW(), '%Y-%m');

-- 上月数据
SELECT COUNT(*) as last_month_count
FROM batch
WHERE farmer_id = ?
  AND DATE_FORMAT(create_time, '%Y-%m') = DATE_FORMAT(DATE_SUB(NOW(), INTERVAL 1 MONTH), '%Y-%m');

-- 计算增长率
-- growth_rate = (current_month_count - last_month_count) / last_month_count * 100
```

## 二、数据获取方案

### 方案一：实时查询（推荐）

#### 优点
- 数据实时准确
- 实现简单
- 无需额外存储

#### 缺点
- 查询压力大
- 响应可能较慢

#### 实现方式
1. 创建专门的统计 API
2. 使用数据库聚合查询
3. 前端定时刷新（可选）

### 方案二：定时统计

#### 优点
- 查询速度快
- 减轻数据库压力
- 可以做复杂计算

#### 缺点
- 数据有延迟
- 需要额外存储
- 实现复杂

#### 实现方式
1. 创建统计数据表
2. 定时任务（每小时/每天）更新统计数据
3. API 直接读取统计表

## 七、性能优化建议

1. **使用 Redis 缓存统计数据**
   - 缓存时间：5-15分钟
   - 减少数据库查询压力

2. **异步加载图表数据**
   - 先显示统计卡片
   - 后加载图表数据

3. **分页加载活动记录**
   - 初始加载10条
   - 滚动加载更多

4. **定时刷新**
   - 每5分钟自动刷新一次
   - 用户可手动刷新
