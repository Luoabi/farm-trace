# 驾驶舱实现说明

## 实现概述

已成功实现驾驶舱的简化版本（方案A），使用现有 API 接口，无需后端修改。

## 实现的功能

### ✅ 1. 核心统计卡片（4个）

#### 超级管理员视图
- 总批次数：调用 `batchAPI.getBatchList()` 获取
- 总商品数：调用 `productAPI.getProductList()` 获取
- 总订单数：调用 `orderAPI.getOrderList()` 获取
- 销售总额：获取所有已发货和已完成订单，前端计算总金额

#### 农户视图
- 我的批次数：调用 `batchAPI.getBatchListByFarmer(farmerId)` 获取
- 我的商品数：调用 `productAPI.getProductListByFarmer(farmerId)` 获取
- 我的订单数：调用 `orderAPI.getOrdersByFarmer(farmerId)` 获取
- 我的销售额：获取我的所有已发货和已完成订单，前端计算总金额

### ✅ 2. 批次状态分布饼图

显示三种状态的批次数量：
- 种植中（status = 1）
- 已收获（status = 2）
- 已售罄（status = 3）

数据来源：
- 超级管理员：`batchAPI.getBatchList()` 获取所有批次
- 农户：`batchAPI.getBatchListByFarmer(farmerId)` 获取自己的批次
- 前端统计各状态数量并更新图表

### ✅ 3. 订单状态分布饼图

显示四种状态的订单数量：
- 待支付（orderStatus = 1）
- 待发货（orderStatus = 2）
- 已发货（orderStatus = 3）
- 已完成（orderStatus = 4）

数据来源：
- 超级管理员：`orderAPI.getOrderList()` 获取所有订单
- 农户：`orderAPI.getOrdersByFarmer(farmerId)` 获取自己的订单
- 前端统计各状态数量并更新图表

### ✅ 4. 最近活动时间线

显示最近的系统活动：
- 最近创建的批次（最多5条）
- 最近创建的订单（最多5条）
- 按时间倒序排列，显示前10条

数据来源：
- 调用相应的列表 API，获取最新的记录
- 前端合并并按时间排序

### ✅ 5. 待处理任务列表（农户专用）

显示农户需要处理的任务：
- 待发货订单：筛选 `orderStatus = 2` 的订单
- 即将收获的批次：筛选7天内要收获的批次（`status = 1` 且 `harvestTime` 在未来7天内）

数据来源：
- 调用 `orderAPI.getOrdersByFarmer(farmerId)` 获取订单
- 调用 `batchAPI.getBatchListByFarmer(farmerId)` 获取批次
- 前端过滤和判断

## 技术实现

### 数据加载流程

```javascript
1. 组件挂载时初始化图表
2. 获取用户信息（从 localStorage）
3. 根据用户角色加载不同数据：
   - 超级管理员：调用全局 API
   - 农户：调用带 farmerId 的 API
4. 加载统计数据
5. 加载分布数据并更新图表
6. 加载最近活动
7. 加载待处理任务
```

### 关键函数

- `initData()`: 主数据加载函数
- `loadAdminStatistics()`: 加载超级管理员统计数据
- `loadFarmerStatistics(farmerId)`: 加载农户统计数据
- `loadDistributionData(userRole, userId)`: 加载分布数据
- `updateCharts()`: 更新图表
- `loadRecentActivities()`: 加载最近活动
- `loadPendingTasks()`: 加载待处理任务
- `refreshData()`: 刷新所有数据

### 图表库

使用 Chart.js 实现数据可视化：
- 批次状态分布：饼图（Pie Chart）
- 订单状态分布：饼图（Pie Chart）

## 性能优化

### 已实现的优化

1. 加载状态：显示 loading 动画，提升用户体验
2. 错误处理：捕获异常并显示错误消息
3. 图表销毁：组件卸载时正确销毁图表，避免内存泄漏
4. 数据缓存：使用 localStorage 缓存用户信息

### 潜在性能问题

1. 数据量大时：
   - 获取所有订单计算销售额（pageSize: 9999）
   - 获取所有批次/订单统计分布（pageSize: 9999）
   - 可能导致请求慢或超时

2. 解决方案：
   - 短期：限制 pageSize，接受数据不完整
   - 长期：后端提供专门的统计 API
