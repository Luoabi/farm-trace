## 二、业务逻辑

### 1. 可取消的订单状态
- ✅ `WAITING_PAYMENT`（待支付）- 可以直接取消
- ✅ `PAID`（已支付）- 可以取消，但需要退款（暂未实现退款逻辑）
- ❌ `SHIPPED`（已发货）- 不允许取消
- ❌ `DELIVERED`（已送达）- 不允许取消
- ❌ `CANCELED`（已取消）- 已经是取消状态

### 2. 取消流程

#### 待支付订单取消
```
1. 验证订单存在
2. 检查订单状态是否为 WAITING_PAYMENT
3. 更新订单状态为 CANCELED
4. 记录取消原因到备注
5. 返回更新后的订单信息
```

#### 已支付订单取消
```
1. 验证订单存在
2. 检查订单状态是否为 PAID
3. 发起退款流程（TODO: 等支付功能实现后补充）
4. 更新订单状态为 CANCELED
5. 记录取消原因到备注
6. 返回更新后的订单信息
```

### 3. 错误处理

| 错误情况 | 错误信息 |
|---------|---------|
| 订单不存在 | "订单不存在" |
| 订单状态不允许取消 | "当前订单状态不允许取消" |

## 三、代码实现

### 1. Service 接口
```java
// OrderService.java
OrderResponse cancelOrder(String id, String reason);
```

### 2. Service 实现
```java
// OrderServiceImpl.java
@Override
public OrderResponse cancelOrder(String id, String reason) {
    Order order = orderMapper.findById(id);
    if (order == null) {
        throw new RuntimeException("订单不存在");
    }

    // 检查订单状态，只有待支付和已支付的订单可以取消
    if (!"WAITING_PAYMENT".equals(order.getOrderStatus()) && 
        !"PAID".equals(order.getOrderStatus())) {
        throw new RuntimeException("当前订单状态不允许取消");
    }

    // 如果订单已支付，这里应该发起退款流程
    if ("PAID".equals(order.getOrderStatus())) {
        // TODO: 发起退款流程
        // refundService.refund(order);
    }

    // 更新订单状态为已取消
    orderMapper.updateStatus(id, "CANCELED");
    
    // 记录取消原因
    if (reason != null && !reason.isEmpty()) {
        String newRemark = (order.getRemark() != null ? order.getRemark() + "\n" : "") 
                         + "取消原因：" + reason;
        order.setRemark(newRemark);
    }
    
    order.setOrderStatus("CANCELED");
    order.setUpdateTime(LocalDateTime.now());
    
    return convertToOrderResponse(order);
}
```

### 3. Controller
```java
// OrderController.java
@PutMapping("/cancel/{id}")
public OrderResponse cancelOrder(@PathVariable String id, 
                                @RequestParam(required = false) String reason) {
    return orderService.cancelOrder(id, reason);
}
```

## 四、使用示例

### 前端调用示例

#### 1. 取消订单（不带原因）
```javascript
import { orderAPI } from '@/api/modules/order';

// 取消订单
const handleCancelOrder = async (orderId) => {
  try {
    const response = await orderAPI.cancelOrder(orderId);
    console.log('订单已取消:', response);
    ElMessage.success('订单已取消');
  } catch (error) {
    console.error('取消订单失败:', error);
    ElMessage.error('取消订单失败: ' + error.message);
  }
};
```

#### 2. 取消订单（带原因）
```javascript
import { orderAPI } from '@/api/modules/order';

// 取消订单并提供原因
const handleCancelOrderWithReason = async (orderId, reason) => {
  try {
    const response = await orderAPI.cancelOrder(orderId, reason);
    console.log('订单已取消:', response);
    ElMessage.success('订单已取消');
  } catch (error) {
    console.error('取消订单失败:', error);
    ElMessage.error('取消订单失败: ' + error.message);
  }
};

// 使用示例
handleCancelOrderWithReason('order001', '不想要了');
```

#### 3. 在订单管理页面中使用
```vue
<template>
  <el-button 
    type="danger" 
    size="small" 
    @click="handleCancel(row)"
    :disabled="!canCancel(row.orderStatus)"
  >
    取消订单
  </el-button>
</template>

<script setup>
import { ElMessage, ElMessageBox } from 'element-plus';
import { orderAPI } from '@/api/modules/order';

// 判断订单是否可以取消
const canCancel = (status) => {
  return status === 'WAITING_PAYMENT' || status === 'PAID';
};

// 取消订单
const handleCancel = async (order) => {
  try {
    // 弹出确认对话框，让用户输入取消原因
    const { value: reason } = await ElMessageBox.prompt(
      '请输入取消原因',
      '取消订单',
      {
        confirmButtonText: '确定',
        cancelButtonText: '取消',
        inputPlaceholder: '请输入取消原因（可选）'
      }
    );
    
    // 调用取消接口
    await orderAPI.cancelOrder(order.id, reason || '');
    ElMessage.success('订单已取消');
    
    // 刷新订单列表
    loadData();
  } catch (error) {
    if (error !== 'cancel') {
      console.error('取消订单失败:', error);
      ElMessage.error('取消订单失败');
    }
  }
};
</script>
```

## 五、订单状态流转图

```
创建订单
   ↓
WAITING_PAYMENT (待支付) ←→ CANCELED (已取消)
   ↓ 支付
PAID (已支付) ←→ CANCELED (已取消，需退款)
   ↓ 发货
SHIPPED (已发货) ✗ 不可取消
   ↓ 送达
DELIVERED (已送达) ✗ 不可取消
```

## 六、注意事项

### 1. 退款功能
当前实现中，已支付订单的退款逻辑尚未实现。在 `cancelOrder` 方法中有 TODO 标记：

```java
if ("PAID".equals(order.getOrderStatus())) {
    // TODO: 发起退款流程
    // refundService.refund(order);
}
```

**后续需要实现：**
- 创建 RefundService
- 集成支付平台的退款 API（微信支付、支付宝等）
- 记录退款状态和退款时间
- 处理退款失败的情况

### 2. 库存恢复
当前实现中，取消订单后没有恢复商品库存。如果系统需要管理库存，应该在取消订单时：

```java
// 恢复商品库存
Product product = productMapper.findById(order.getProductId());
product.setStock(product.getStock() + order.getQuantity());
productMapper.update(product);
```

### 3. 取消原因记录
取消原因目前记录在订单的 `remark` 字段中。如果需要更详细的取消记录，建议：

- 创建独立的订单取消记录表
- 记录取消时间、取消人、取消原因等信息
- 便于后续数据分析

### 4. 权限控制
当前接口没有权限验证，建议添加：

- 只有订单创建者（客户）可以取消自己的订单
- 超级管理员可以取消任何订单
- 农户不能取消订单（只能拒绝发货）
