# 商品管理 - 库存销量分析

## 🎯 结论：商品表**不需要**库存和销量字段

## 📊 业务模型分析

### 你的系统架构：

```
农户 (Farmer)
    ↓
商品 (Product) - 商品品类信息
    ↓
批次 (Batch) - 实际种植批次（有产量数据）
    ↓
生长记录 (GrowthRecord) - 生长过程记录
    ↓
订单 (Order) - 销售订单
```

### 数据关系：

```
商品：西昌葡萄
├─ 批次1：2024-01批
│   ├─ 计划产量：1000kg
│   ├─ 实际产量：1200kg  ← 这就是库存
│   └─ 已售：800kg
├─ 批次2：2024-02批
│   ├─ 计划产量：1500kg
│   ├─ 实际产量：1600kg
│   └─ 已售：500kg
└─ 批次3：2024-03批
    ├─ 计划产量：800kg
    ├─ 实际产量：900kg
    └─ 已售：0kg
```

## ✅ 推荐方案

### 1. 商品表（Product）- 品类信息

**作用：** 定义商品品类和基本信息

**字段：**
```sql
CREATE TABLE product (
    id VARCHAR(36),
    farmer_id VARCHAR(36),
    product_code VARCHAR(50),
    product_name VARCHAR(100),
    category VARCHAR(50),
    description TEXT,
    price DECIMAL(10,2),        -- 参考价格
    unit VARCHAR(20),
    specification VARCHAR(100),
    production_place VARCHAR(100),
    image_url VARCHAR(255),
    status TINYINT,
    -- ❌ 不需要 stock（库存）
    -- ❌ 不需要 sales_count（销量）
);
```

### 2. 批次表（Batch）- 实际库存

**作用：** 管理每个种植批次的产量和库存

**字段：**
```sql
CREATE TABLE batch (
    id VARCHAR(36),
    product_id VARCHAR(36),
    batch_number VARCHAR(50),
    planned_quantity DECIMAL(10,2),   -- 计划产量
    actual_quantity DECIMAL(10,2),    -- 实际产量（可用库存）
    -- 可选：添加已售数量
    sold_quantity DECIMAL(10,2),      -- 已售数量
    -- 或者从订单表统计
);
```

### 3. 订单表（Order）- 销售记录

**作用：** 记录每笔销售

**字段：**
```sql
CREATE TABLE order (
    id VARCHAR(36),
    product_id VARCHAR(36),
    batch_id VARCHAR(36),
    quantity DECIMAL(10,2),  -- 购买数量
    total_price DECIMAL(10,2),
    -- ...
);
```

## 📈 如何查询库存和销量

### 查询某个商品的总库存：

```sql
-- 方案1：从批次表统计
SELECT 
    p.product_name,
    SUM(b.actual_quantity) as total_stock,
    SUM(b.sold_quantity) as total_sold,
    SUM(b.actual_quantity - b.sold_quantity) as available_stock
FROM product p
LEFT JOIN batch b ON p.id = b.product_id
WHERE p.id = 'product-001'
GROUP BY p.id;

-- 方案2：从订单表统计销量
SELECT 
    p.product_name,
    SUM(b.actual_quantity) as total_stock,
    COALESCE(SUM(o.quantity), 0) as total_sold,
    SUM(b.actual_quantity) - COALESCE(SUM(o.quantity), 0) as available_stock
FROM product p
LEFT JOIN batch b ON p.id = b.product_id
LEFT JOIN `order` o ON b.id = o.batch_id AND o.order_status != 'CANCELED'
WHERE p.id = 'product-001'
GROUP BY p.id;
```

### 查询某个批次的库存：

```sql
SELECT 
    b.batch_number,
    b.actual_quantity as total_stock,
    COALESCE(SUM(o.quantity), 0) as sold,
    b.actual_quantity - COALESCE(SUM(o.quantity), 0) as available
FROM batch b
LEFT JOIN `order` o ON b.id = o.batch_id AND o.order_status != 'CANCELED'
WHERE b.id = 'batch-001'
GROUP BY b.id;
```

## 💡 最佳实践

### 库存管理流程：

1. **创建商品** → 定义商品品类（西昌葡萄）
2. **创建批次** → 种植一批葡萄（2024-01批，计划1000kg）
3. **记录生长** → 记录生长过程
4. **收获入库** → 更新批次的实际产量（实际1200kg）
5. **创建订单** → 客户下单购买（从某个批次扣减库存）
6. **统计查询** → 查看商品的总库存和销量

### 优点：

- ✅ 符合农产品溯源的业务逻辑
- ✅ 每个批次独立管理，可追溯
- ✅ 支持同一商品多批次并存
- ✅ 避免数据冗余和不一致
- ✅ 灵活的库存管理

## 📝 总结

**商品（Product）= 品类信息**
- 不需要库存和销量字段
- 专注于商品的基本信息管理

**批次（Batch）= 实际库存单位**
- 有实际产量（库存）
- 可以添加已售数量字段
- 或者从订单表统计销量

**订单（Order）= 销售记录**
- 记录每笔销售
- 关联到具体批次
- 用于统计销量

这样的设计更符合农产品溯源系统的业务逻辑！
