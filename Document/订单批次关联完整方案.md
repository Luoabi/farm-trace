# 订单批次关联完整方案

## 问题分析

### 原始问题
创建订单时报错：
```
Cannot add or update a child row: a foreign key constraint fails 
(`xichang_trace`.`order`, CONSTRAINT `fk_order_batch` 
FOREIGN KEY (`batch_id`) REFERENCES `batch` (`id`))
```

**原因**：
1. 订单表的 `batch_id` 字段有外键约束，必须引用 `batch` 表中存在的ID
2. 前端传递空字符串 `''`，不是有效的批次ID
3. 数据库不允许 `batch_id` 为 NULL（字段定义为 NOT NULL）

### 用户建议
"为什么不用商品ID去批次里面找到该批次ID？" ✅ 非常好的建议！

## 解决方案

### 核心思路
**自动批次关联**：通过商品ID自动查找对应的批次，无需前端传递批次ID。

### 优先级策略
```
1. 如果前端指定了批次ID → 使用指定的批次
2. 如果没有指定批次ID → 通过商品ID查找批次
   2.1 找到批次 → 使用找到的批次（取最新的）
   2.2 没找到批次 → 不关联批次（batch_id = NULL）
```

## 实现步骤

### 1. 数据库修改

#### 1.1 修改订单表结构
允许 `batch_id` 为 NULL，支持不关联批次的订单。

```sql
-- 执行迁移脚本
-- 文件：migration_fix_order_batch.sql

-- 1. 删除外键约束
ALTER TABLE `order` DROP FOREIGN KEY `fk_order_batch`;

-- 2. 修改 batch_id 字段为可空
ALTER TABLE `order` MODIFY COLUMN `batch_id` VARCHAR(36) NULL COMMENT '批次ID（可选）';

-- 3. 修改 batch_number 字段为可空
ALTER TABLE `order` MODIFY COLUMN `batch_number` VARCHAR(50) NULL COMMENT '批次编号（可选）';

-- 4. 重新添加外键约束（允许NULL）
ALTER TABLE `order` 
ADD CONSTRAINT `fk_order_batch` 
FOREIGN KEY (`batch_id`) REFERENCES `batch` (`id`) 
ON DELETE SET NULL 
ON UPDATE CASCADE;
```

**执行方法**：
```bash
# 在数据库中执行
mysql -u root -p xichang_trace < migration_fix_order_batch.sql
```

### 2. 后端修改

#### 2.1 添加批次查询方法

**BatchMapper.java**：
```java
// 根据商品ID查询批次列表（按创建时间倒序）

```

**BatchMapper.xml**：
```xml
<select id="findByProductId" resultMap="BatchResultMap">
    SELECT * FROM batch 
    WHERE product_id = #{productId}
```

#### 2.2 修改订单创建逻辑

**OrderServiceImpl.java** - `createOrder()` 方法：

```java
// 获取批次信息和农户信息
Batch batch = null;
String farmerId = null;
String batchId = null;
String batchNumber = null;

// 策略1：如果提供了批次ID，使用指定的批次
if (request.getBatchId() != null && !request.getBatchId().isEmpty()) {
    batch = batchMapper.findById(request.getBatchId());
    if (batch == null) {
        throw new RuntimeException("指定的批次不存在");
    }
    farmerId = batch.getFarmerId();
    batchId = batch.getId();
    batchNumber = batch.getBatchNumber();
} else {
    // 策略2：通过商品ID自动查找批次
    List<Batch> batches = batchMapper.findByProductId(request.getProductId());
    
    if (batches != null && !batches.isEmpty()) {
        // 找到批次，使用第一个（最新的）
        batch = batches.get(0);
        farmerId = batch.getFarmerId();
        batchId = batch.getId();
        batchNumber = batch.getBatchNumber();
    } else {
        // 策略3：没有批次，从商品信息获取农户ID
        farmerId = product.getFarmerId();
        batchId = null;
        batchNumber = null;
    }
}

// 查询农户信息
User farmer = userMapper.findById(farmerId);

// 创建订单
Order order = new Order();
order.setBatchId(batchId);  // 可能为 NULL
order.setBatchNumber(batchNumber);  // 可能为 NULL
order.setFarmerId(farmer.getId());
// ... 其他字段
```

## 数据流程

### 完整流程图

```
用户下单
  ↓
前端传递：productId, batchId=''
  ↓
后端接收订单请求
  ↓
查询商品信息（获取 product.farmerId）
  ↓
判断是否提供 batchId？
  ├─ 是 → 使用指定批次
  └─ 否 → 通过 productId 查找批次
       ├─ 找到批次 → 使用找到的批次（最新的）
       │   ├─ farmerId = batch.farmerId
       │   ├─ batchId = batch.id
       │   └─ batchNumber = batch.batchNumber
       └─ 未找到批次 → 不关联批次
           ├─ farmerId = product.farmerId
           ├─ batchId = NULL
           └─ batchNumber = NULL
  ↓
查询农户信息
  ↓
创建订单（包含正确的 farmerId 和 batchId）
  ↓
订单创建成功
```

## 三种场景

### 场景1：指定批次下单
```
用户选择批次 → 前端传递 batchId → 后端使用指定批次
```
- **适用**：需要溯源的高端农产品
- **优点**：精确关联批次，完整溯源信息

### 场景2：自动关联批次
```
用户下单 → 前端不传 batchId → 后端自动查找批次 → 关联最新批次
```
- **适用**：商品有批次但用户不需要选择
- **优点**：自动化，用户体验好

### 场景3：无批次订单
```
用户下单 → 商品没有批次 → 订单不关联批次
```
- **适用**：普通农产品快速销售
- **优点**：简化流程，不需要维护批次

## 数据库查询验证

```sql
-- 1. 查看订单的批次关联情况
SELECT 
  o.id,
  o.order_number,
  o.product_id,
  o.batch_id,
  o.batch_number,
  o.farmer_id,
  o.farmer_name,
  CASE 
    WHEN o.batch_id IS NULL THEN '无批次'
    ELSE '有批次'
  END AS batch_status
FROM `order` o
ORDER BY o.create_time DESC
LIMIT 10;

-- 2. 验证农户ID的正确性
SELECT 
  o.id AS order_id,
  o.product_id,
  o.farmer_id AS order_farmer_id,
  p.farmer_id AS product_farmer_id,
  b.farmer_id AS batch_farmer_id,
  CASE 
    WHEN o.batch_id IS NULL THEN 
      CASE WHEN o.farmer_id = p.farmer_id THEN '✓ 正确（来自商品）' ELSE '✗ 错误' END
    ELSE 
      CASE WHEN o.farmer_id = b.farmer_id THEN '✓ 正确（来自批次）' ELSE '✗ 错误' END
  END AS status
FROM `order` o
LEFT JOIN product p ON o.product_id = p.id
LEFT JOIN batch b ON o.batch_id = b.id
ORDER BY o.create_time DESC;

-- 3. 查看商品的批次数量
SELECT 
  p.id AS product_id,
  p.product_name,
  p.farmer_id,
  COUNT(b.id) AS batch_count
FROM product p
LEFT JOIN batch b ON p.id = b.product_id AND b.status != -1
GROUP BY p.id, p.product_name, p.farmer_id
ORDER BY batch_count DESC;
```

## 注意事项

### 1. 批次选择策略
- 当前使用**最新批次**（按 create_time DESC）
- 可以改为使用**状态为"进行中"的批次**
- 可以改为使用**库存最多的批次**

### 2. 性能优化
- 批次查询添加索引：`CREATE INDEX idx_batch_product ON batch(product_id, create_time)`
- 考虑缓存商品的最新批次ID

### 3. 业务规则
- 如果商品有多个批次，是否需要用户选择？
- 批次状态是否影响订单创建？
- 批次库存是否需要扣减？

### 4. 数据迁移
- 历史订单的 batch_id 可能为空字符串，需要更新为 NULL
- 执行迁移脚本后，检查历史数据
