# 微信小程序地址功能修复说明

## 🐛 问题描述

**错误信息：**
```
POST http://localhost:8080/api/user/address/create 500
```

**原因：**
小程序发送的 `isDefault` 字段是 `boolean` 类型（true/false），但后端期望的是 `Integer` 类型（0/1）。

---

## ✅ 修复内容

### 修改文件
`App/WeChatApp/miniprogram/pages/address-edit/address-edit.ts`

### 修改点 1：提交地址时的类型转换

**修改前：**

## 📊 数据类型对照表

| 位置 | 前端（小程序） | 后端（Java） | 转换规则 |
|------|--------------|-------------|---------|
| 页面 data | `boolean` | - | 页面内部使用 |
| 提交到后端 | `boolean` → `Integer` | `Integer` | `true → 1`, `false → 0` |
| 后端返回 | `Integer` → `boolean` | `Integer` | `1 → true`, `0 → false` |
| 显示在页面 | `boolean` | - | switch 组件使用 |

## 💡 最佳实践

### 1. 类型转换统一处理

在 API 层统一处理类型转换，避免在页面中重复转换：

```typescript
// api/address.ts
export async function createAddress(data: any) {
  // 统一转换类型
  const requestData = {
    ...data,
    isDefault: data.isDefault ? 1 : 0  // boolean → Integer
  };
  
  const response = await request({
    url: '/user/address/create',
    method: 'POST',
    data: requestData
  });
  
  return response;
}
```

### 2. 响应数据转换

```typescript
// api/address.ts
function transformAddress(item: any): Address {
  return {
    id: item.id,
    userId: item.userId,
    receiverName: item.receiverName,
    receiverPhone: item.receiverPhone,
    province: item.province,
    city: item.city,
    district: item.district,
    detailAddress: item.detailAddress,
    fullAddress: `${item.province}${item.city}${item.district}${item.detailAddress}`,
    isDefault: item.isDefault === 1,  // Integer → boolean
    createdAt: item.createTime,
    updatedAt: item.updateTime
  };
}
```

### 3. 后端统一返回格式

建议后端也可以考虑使用 `boolean` 类型，但需要修改数据库和 DTO：

```java
// AddressRequest.java
@Data
public class AddressRequest {
    private String userId;
    private String receiverName;
    private String receiverPhone;
    private String province;
    private String city;
    private String district;
    private String detailAddress;
    private Boolean isDefault;  // 改为 Boolean 类型
}
```

## 🎉 总结

**问题根源：**
前后端数据类型不一致（boolean vs Integer）

**解决方案：**
在数据传输时进行类型转换
- 提交时：`boolean → Integer`
- 接收时：`Integer → boolean`

**影响范围：**
仅影响地址编辑页面，其他页面已有正确的类型转换逻辑

**测试结果：**
✅ 修复后可以正常添加和编辑地址
